# Готовые библиотеки для конвертации

Сравнение выполнено локально на пересчитанной январской ведомости, карточке
затрат, акте PNG и PDF-превью справки DOCX. Документы в сетевые API не отправлялись.

| Решение | Что проверено | Результат |
| --- | --- | --- |
| Docling 2.150.0, Excel-backend | XLSX после пересчёта Calc | Нашёл отдельные блоки метаданных и таблицу из четырёх столбцов. Выбран для XLSX. |
| MarkItDown 0.1.9 | Тот же XLSX | Заголовок документа стал заголовком всей таблицы; появились `Unnamed` и `NaN`. |
| PyMuPDF4LLM 2.1 | XLSX через PDF | Данные извлеклись в текст, таблица не сохранилась. |
| PyMuPDF4LLM 2.1 с Tesseract | Скан карточки, PNG-акт, DOCX через PDF | PNG-акт прочитан; на карточке потеряны подпись, структура и важные суммы; таблица DOCX стала текстом. |

Это результаты конкретных версий и настроек, а не универсальная оценка качества.
Дополнительные модели и настройки могут изменить результат.

## Полный PDF/OCR-пайплайн Docling

Дополнительно установлен и проверен нейросетевой PDF-пайплайн Docling 2.150.0:
локальная модель разметки Heron, модели TableFormer и Tesseract CLI (`rus+eng`).
Прогоны выполнены на CPU, с заранее скачанными моделями и отключёнными удалёнными
сервисами. В Windows используется штатный PDFium-бэкенд: нативный docling-parse
не смог открыть свои ресурсы из пути установки с кириллицей.

| Вход | Модель/режим | Наблюдение |
| --- | --- | --- |
| Карточка затрат, скан, 17 столбцов | TableFormer V1 Accurate | Достигнут лимит декодирования 1024; структура отброшена, получена одна ячейка. |
| Та же карточка | TableFormer V1 Fast | Получено 16 столбцов; встречаются объединённые и смещённые значения. |
| Та же карточка | TableFormer V2 | Получено 15 столбцов вместо 17; пять из шести контрольных сумм в итоговом Markdown не прошли проверку. |
| Акт связи PNG | TableFormer V2, Tesseract PSM 6 | Сумма и получатель сохранены; все непробельные символы сопоставлены с координатами. |
| Справка ИТ DOCX через изолированный PDF-экспорт | TableFormer V2, встроенный текст PDF | Сохранены таблица из двух столбцов и сумма; нет несопоставленных непробельных символов. |
| УПД PDF | TableFormer V2, встроенный текст | Текст извлечён; три символа остались без привязки на исходной обрезанной странице. |

Поэтому полный Docling добавлен как явный `--backend docling`, а `classic`
остаётся режимом по умолчанию. Уже проверенные файлы в `output/all` не заменяются
результатами экспериментального прогона. Примеры и машинная сводка находятся в
`output/docling/`; большие модели, исходники и результаты не входят в git.

```powershell
.venv\Scripts\python.exe document_ocr.py models-download
.venv\Scripts\python.exe document_ocr.py "input.pdf" "output/docling.md" --backend docling
```

По умолчанию используется TableFormer V2. Для сравнения доступны
`--docling-table-model v1` и `--docling-table-model v1-fast`;
их веса устанавливаются командой `models-download --table-model both`.
Для цифрового PDF без OCR можно передать `--ocr never`.
Для полного OCR страницы — `--ocr always`; для изображений автоматически
выбирается PSM 6, для PDF — PSM 11. Значения можно переопределить через `--psm`.

`docling_layout.py` связывает готовую разметку и Markdown Docling с настоящими
глифами PyMuPDF/Tesseract. Несовпадающие символы помечаются как несопоставленные;
координаты не придумываются. Дополнительные интеграционные тесты включаются
переменной `OCR_DOCLING_TESTS=1`. Один из них запрещает сетевые подключения
во время реальной конвертации и проверяет подсветку второй одинаковой суммы.

## Реализация

- Docling сам читает XLSX через openpyxl, выделяет области таблиц и сериализует Markdown.
- Для XLSX нейросетевые модели не нужны; для полного PDF/OCR-режима добавлены
  компоненты `format-pdf` и `models-local` и отдельная команда загрузки моделей.
- LibreOffice/UNO пересчитывает формулы и сообщает отображаемый текст и физические
  границы ячеек из того же документа, который экспортируется в PDF.
- Небольшой адаптер `spreadsheet_layout.py` связывает ячейки Docling с настоящими
  PDF-глифами PyMuPDF и позициями в Markdown. Уникальные маркеры ячеек предотвращают
  путаницу между одинаковыми суммами в разных строках.
- Геометрия ячеек используется только при конвертации. В результатах сохраняются
  исключительно `bbox_normalized` символов; сырые ячейки не дублируются в JSON.
- Символьные области берутся из PDF, а не получаются делением области слова.
  Глифы с нулевой или отсутствующей областью не подменяются выдуманными координатами;
  сохраняется предупреждение о неполном соответствии.
- Markdown представляет значения ячеек; изображения и графики остаются в PDF-превью.
- Для сканов сохранены Tesseract, OpenCV и проверенные исправления мелких чисел
  и разрозненных подписей. Замена всего пути на другой конвертер должна сначала
  проходить те же проверки сумм, структуры и координат.
