# Задача

## Полное описание

Вам необходимо разработать систему, которая сопоставляет показатели итогового отчета с первичными учетными документами,
на основании которых он был сформирован.
Решение должно находить расхождения в суммах, показателях и других значениях, показывать источник каждого несоответствия
и формировать итоговое заключение о достоверности отчета. Пользователь должен иметь возможность понять, из какого
документа получено ожидаемое значение и почему конкретная строка отчета считается корректной или ошибочной.

## Вводные данные

Коллекция включает итоговый отчет (КФЗ) и связанные первичные и расчетные документы в разных форматах (PDF, DOCX, XLSX,
PNG), в том числе сканы. Документы различаются по структуре и формулировкам; связь с показателями отчета определяется по
реквизитам (номер договора, период, номер документа) и содержанию. В наборе могут встречаться дубли, документы другого
периода или договора, а для части показателей подтверждающих данных может быть недостаточно. В промышленной эксплуатации
входные документы могут быть существенно сложнее для извлечения и интерпретации: низкокачественные сканы, нестандартные
формы, неполные или ошибочные реквизиты, различная верстка и дополнительные форматы.

## Ожидаемый результат работы решения

На вход система получает итоговый отчет и набор связанных первичных документов. На выходе должен формироваться результат
сверки, позволяющий проверить каждое найденное расхождение.

1. Статус проверки каждого показателя или строки отчета.
2. Фактическое значение из отчета и ожидаемое значение, рассчитанное или извлеченное из первичных документов.
3. Размер расхождения, если значения не совпадают.
4. Ссылка на первичный документ и конкретный фрагмент, который подтверждает ожидаемое значение.
5. Категория несоответствия, например расхождение суммы, пропущенный документ, дублирование, неверный период или
   несовпадение другого показателя.
6. Итоговое заключение о достоверности отчета с краткой сводкой найденных проблем.

## Ограничения

Через любые внешние API можно передавать только открытые (/не конфиденциальные) данные

## Критерии

- 8 баллов: корректно извлекаются показатели итогового отчета.
- 8 баллов: корректно извлекаются значения и реквизиты первичных учетных документов.
- 4 балла: отчетные показатели связываются с правильными источниками по идентификаторам, периодам и другим признакам.
- 8 баллов: несколько первичных документов корректно агрегируются для проверки одного итогового показателя.
- 5 баллов: учтены периоды, единицы измерения, знаки и правила округления.
- 3 балла: дубли, пропущенные документы и неоднозначные связи обрабатываются явно.
- 12 баллов: корректно обнаруживаются расхождения в суммах и других проверяемых показателях.
- 8 баллов: корректные строки не помечаются как ошибочные.
- 4 балла: несоответствия классифицируются по типу, включая сумму, период, пропуск, дублирование и связь документов.
- 6 баллов: каждый результат связан с конкретным первичным документом и подтверждающим фрагментом.
- 6 баллов: итоговый отчет разделяет корректные, ошибочные и непроверенные показатели и содержит понятную сводку.
- 4 балла: система отличает реальное расхождение от недостатка данных для проверки.
- 4 балла: обработаны разные форматы, поврежденные файлы, отсутствующие поля и технические ошибки.
- 8 баллов: предоставлены Dockerfile и, для многокомпонентного решения, Docker Compose; решение запускается в чистом
  окружении по инструкции без ручного изменения исходного кода.
- 6 баллов: README содержит требования к окружению, команды запуска и остановки, зависимости, настройки и переменные
  окружения, перечень внешних сервисов.
- 6 баллов: описаны архитектура, ключевые компоненты и поток данных от входа до результата; приведены не менее двух
  типовых use cases с примером входа и ожидаемого результата.

## Описание набора данных

Вместе с задачей идёт набор данных. Далее идёт описание этого набора данных:

```
НАБОР ДАННЫХ ДЛЯ КЕЙСА 19

Итоговый отчет: «01_Карточка_учета_фактических_затрат_этап_3.pdf».
Проверяемая строка отчета: «3 этап, 2026 г.».
Договор: 24/03/15-01.
Период подтверждающих документов: 01.01.2026–31.05.2026.

Остальные файлы в папке являются связанными первичными или расчетными документами. Документы представлены в разных
форматах и могут отличаться структурой, расположением реквизитов и формулировками назначения расходов. Наименование
статьи КФЗ не обязательно указано в документе дословно — связь необходимо определять по реквизитам и содержанию
операции.

При проверке необходимо учитывать номер документа, договор, период, содержание операции и сумму. В наборе могут
встречаться повторные документы, документы другого периода или другого договора.

Часть детализированных показателей КФЗ может не иметь отдельного подтверждающего документа. Такие показатели следует
отделять от подтвержденных и ошибочных и обозначать как непроверенные / недостаточно данных.
```
