# Работающий Docker без Docker Desktop

На этой машине настроен **локальный Linux Docker Engine 29.9.3** в QEMU.
Используется программная эмуляция TCG: работающий Hyper-V, WSL и Docker Desktop
для этого варианта не требуются. Windows Sandbox в обработке документов не участвует.

## Запуск и остановка

Из папки проекта после перезагрузки Windows:

```powershell
python docker_vm.py start
```

Проверка сервера:

```powershell
python docker_vm.py status
```

В выводе Docker должны присутствовать **Client** и **Server**. CLI добавлен в
пользовательский PATH (доступен новым терминалам); скрипт также сам находит
`.tools/docker/docker.exe`.

Остановка Linux-машины, освобождающая её память:

```powershell
python docker_vm.py stop
```

Сначала завершите обработку документов и сборку образов. Виртуальный диск,
установленные пакеты и образы сохраняются между запусками. Автозапуск при входе
в Windows не настраивался.

## Работа со скриптом

```powershell
python document_ocr.py sandbox-build
python document_ocr.py "данные/02_01_Ведомость_ЗП_Январь_2026.xlsx" "output/payroll.md"
```

Контекст Docker **`ocr-local-vm`** выбран текущим. При необходимости:

```powershell
.\.tools\docker\docker.exe context use ocr-local-vm
.\.tools\docker\docker.exe version
.\.tools\docker\docker.exe run --rm hello-world
```

## Как это устроено

- QEMU 11.1.0, Alpine Linux 3.24.4, ядро Linux 6.18.
- Docker Engine 29.9.3 в гостевой Linux; Docker CLI 29.9.3 и Buildx 0.39.0 на Windows.
- 3072 МБ RAM и 2 виртуальных CPU; qcow2-диск с верхним размером 32 ГиБ
  увеличивается по мере записи. Программная эмуляция медленнее аппаратной,
  особенно при первой сборке образа.
- Все файлы работающей VM: `%USERPROFILE%\.docker\ocr-vm`.
  Windows-программы QEMU используют этот путь без кириллицы; их проверенные
  установочные архивы также сохранены в `.tools/docker-vm/downloads`.
- Linux-пакеты установлены из подписанных репозиториев Alpine. QEMU загружен
  по ссылке с сайта проекта, проверен опубликованный SHA-512; ISO Alpine
  проверен по SHA-256. Buildx проверен по digest GitHub, Windows-плагин подписан Docker Inc.
- Docker API доступен только через **127.0.0.1:49179** с взаимной TLS-аутентификацией.
  Удалённые адреса не открываются. CA и клиентские ключи индивидуальны для этой VM.
  Приватные ключи ограничены ACL текущего пользователя.
- Управление остановкой идёт через SSH на **127.0.0.1:49177**, только по ключу,
  с закреплённым ключом сервера. Парольный SSH-вход отключён.
- Bootstrap-консоль QEMU слушает только **127.0.0.1:49178**; установлен случайный
  пароль root. Рабочий API скрипта эту консоль не использует.
- Для Go-процессов Docker в гостевой системе отключены CPU-оптимизации
  (`GODEBUG=cpu.all=off`) для совместимости с программной эмуляцией.

## Документы и изоляция

Python/OCR запускается на Windows. Входной Office-файл передаётся через stdin
во временный Docker volume. Это решает различие путей Windows и Linux:
каталоги компьютера не монтируются в контейнеры и не публикуются в VM.

Контейнер LibreOffice получает volume **только для чтения**, запускается без
сети, без capabilities, от непривилегированного пользователя и с ограничениями
ресурсов. После обработки контейнер и временный volume удаляются. Результаты
возвращаются через stdout с проверкой имён и размеров файлов.

`office_sandbox.py` разрешает этот единственный loopback TCP-контекст только
при совпадении сохранённых SHA-256 CA, сертификата и ключа. Произвольные
TCP/SSH Docker-серверы по-прежнему запрещены. Исходные документы остаются на
этом компьютере; публичные репозитории используются для установки пакетов и образов.

## Ограничения

Это настроенное локальное окружение этой машины. Установленные бинарники,
ключи и виртуальный диск не входят в git. На другом компьютере можно использовать
обычный локальный Linux Engine или Docker Desktop; те же Dockerfile и CLI
конвертера поддерживаются без необходимости QEMU.

Источники:

- [QEMU для Windows](https://www.qemu.org/download/#windows)
- [Docker: защита соединения с daemon через TLS](https://docs.docker.com/engine/security/protect-access/)
- [Alpine Linux](https://alpinelinux.org/)
